# 위임 규칙 (Claude 설계 → Codex 구현)

Claude는 설계와 계획, Codex는 구현과 테스트를 맡는다. 계획 파일이 둘 사이의 계약이다.

## 1. 역할

| 단계 | 담당 | 하는 일 |
|---|---|---|
| 설계 · 계획 | Claude | 요구 해석, 구조 결정, `docs/plans/NNN-이름.md` 작성 (틀은 `docs/plans/_TEMPLATE.md`) |
| 구현 · 테스트 | Codex | 계획 파일대로 구현하고 완료 조건을 실행해서 결과를 보고한다 |
| 검증 | Claude | `git diff --stat`과 완료 조건 실행 결과로 확인한다. 전체 diff는 필요할 때만 읽는다 |
| git (브랜치, 커밋, PR, 병합) | Claude | Codex는 working tree만 바꾼다 |
| 삭제 | Claude | Codex는 보고에 적고, Claude가 사용자 확인을 받아 실행한다 |

## 2. 위임 기준

- 완료 조건을 명령 한 줄로 쓸 수 있으면 위임한다. 쓰기 어려우면 Claude가 직접 한다.
- 계획 작성이 구현보다 더 큰 변경(파일 1~2개, 수십 줄)은 직접 한다. 이 기준은 가설이다. 측정해서 조정한다.

## 3. 위임 방법

1. Claude가 계획 파일을 쓰고 사용자 승인을 받는다.
2. Codex 플러그인이 있으면 `/codex:rescue --background docs/plans/NNN-이름.md 대로 구현하고 완료 조건을 실행해서 결과를 보고해라`로 위임한다. 없으면 사용자에게 같은 문장을 Codex에서 실행하라고 안내한다.
3. `/codex:status`, `/codex:result`로 확인한다. 끝나면 검증한다.

## 4. Codex가 지킬 것 (계획에 매번 적지 않아도 지킨다)

- 브랜치, 커밋, push, PR을 만들지 않는다. 변경만 working tree에 남기고 보고한다.
- 파일과 브랜치를 삭제하지 않는다. 필요하면 보고에 적는다.
- `--no-verify` 같은 hook 우회 옵션을 쓰지 않는다. `master` / `main`을 건드리지 않는다. `.env`, `.env.*` 파일을 만들지 않는다.
- 계획에 없는 파일을 바꾸지 않는다. 막히면 추측하지 말고 멈추고 보고한다.
- 보고에 실행한 명령과 결과 요약, 바뀐 파일 목록을 쓴다.

## 5. 실패했을 때

- 완료 조건을 못 채우면 Claude가 실패 원인만 짚어 계획을 고치고 다시 위임한다.
- 두 번 실패하면 계획 자체를 다시 본다. 그래도 안 되면 Claude가 직접 구현한다.
